# Quest Editor — правила проекта

Полная спецификация: `Docs/QuestEditor_Spec.md`. Перед любой работой прочитай её раздел,
относящийся к текущему этапу.

## Окружение (строго)

- **Unity 2023.1.22f1.** Используй только API, существующие в этой версии.
  Если не уверен, что API есть в 2023.1 — скажи об этом и предложи вариант, который точно есть.
- Известные ограничения 2023.1, которые нельзя нарушать:
  - атрибутов `[UxmlElement]` / `[UxmlAttribute]` нет (появились в 2023.2). Собственные
    VisualElement'ы создавай в коде; если нужен UXML — только через `UxmlFactory`/`UxmlTraits`;
  - Unity Graph Toolkit недоступен (Unity 6.2+). Граф делаем на `UnityEditor.Experimental.GraphView`;
  - `FindObjectOfType` объявлен устаревшим — и он нам всё равно запрещён (см. ниже).
- **C# 9**, API Compatibility Level .NET Standard 2.1. Не используй: `record`, `init`-аксессоры
  (нет `IsExternalInit`), file-scoped namespace, `global using`, required members и прочее из C# 10+.
- Пакет: `Packages/com.vokazhira.quest-editor/` (embedded UPM package).
  Пример: `Assets/QuestEditorDemo/` (на время разработки), затем переносится в `Samples~/`.
- Namespaces: `Vokazhira.QuestEditor` (Runtime), `Vokazhira.QuestEditor.Editor` (Editor).

## Порядок работы

1. Работай строго по этапам спецификации. Один этап за раз.
2. После каждого этапа:
   - перечисли созданные и изменённые файлы;
   - опиши, что теперь работает;
   - перечисли проверки, которые ты **фактически** выполнил, и их результат;
   - дай короткий чек-лист того, что я должен проверить руками в Unity;
   - назови известные ограничения;
   - **ОСТАНОВИСЬ и жди моего подтверждения.** Ты не видишь Unity Editor, поэтому
     ошибки компиляции и UI я сообщу сам.
3. Никогда не утверждай, что код компилируется, тесты проходят или UI работает,
   если ты это не проверил. Если проверить нельзя — так и напиши.
4. Если неоднозначность влияет на архитектуру — задай один конкретный вопрос.
   В остальных случаях принимай решение сам и записывай его в `Docs/Decisions.md`
   (дата, решение, причина).
5. Не трогай файлы вне `Packages/com.vokazhira.quest-editor/`, `Assets/QuestEditorDemo/`,
   `Docs/` и `CLAUDE.md` без моего разрешения. Не меняй `ProjectSettings/` и `Packages/manifest.json`
   без согласования.
6. Не генерируй весь проект одним махом. Небольшие файлы, один класс — один файл.

## Стиль кода

- Не оставляй `//`-комментарии рядом с полями и перед методами. Если пояснение нужно —
  только `/// <summary>` (XML-документация) и `[Tooltip]` для сериализуемых полей.

## Unity-специфика

- **Не создавай `.meta`-файлы** — их генерирует Unity.
- В asmdef ссылайся на сборки **по имени**, не по GUID.
- Runtime-сборка не ссылается на `UnityEditor` ни в каком виде. Editor-сборка: `includePlatforms: ["Editor"]`.
- `[SerializeReference]`: переименование/перенос класса ломает данные — при рефакторинге
  добавляй `[UnityEngine.Scripting.APIUpdating.MovedFrom(...)]`. Не используй generic-типы
  в `[SerializeReference]`-полях.
- Редактор должен переживать domain reload и перекомпиляцию: храни GUID открытого ассета
  в `[SerializeField]` окна и пересобирай UI в `CreateGUI()`.
- Модель данных — единственный источник правды. Визуальные элементы GraphView не хранят
  уникальных данных и всегда могут быть пересобраны из модели.
- Изменения модели в редакторе — только через `Undo.RecordObject` / `SerializedObject`.
- Не сканируй проект каждый кадр (`AssetDatabase.FindAssets` — только по событию или запросу).

## Запреты в коде

- Глобальные статические менеджеры/синглтоны как основной способ связи.
- `FindObjectOfType` / `FindFirstObjectByType` для поиска сервисов.
- `PlayerPrefs` для прогресса.
- Изменяемый прогресс игрока в ScriptableObject.
- `Resources.Load` как механизм поиска заданий.
- Сторонние пакеты (включая Newtonsoft JSON) без моего согласия. JSON — через `JsonUtility`.
- Один «божественный» класс, который одновременно рисует UI, исполняет квесты, сохраняет и выдаёт награды.
- Лишние абстракции «на будущее», пустые классы и пустые папки ради структуры.

## Тесты

- Unity Test Framework (версию возьми из `Packages/manifest.json`, не выдумывай).
- Логику Runtime пиши как обычные C#-классы, чтобы её можно было покрыть EditMode-тестами.
- Запуск из командной строки (работает, только если проект **закрыт** в Unity Editor):

  ```
  "C:\Program Files\Unity\Hub\Editor\2023.1.22f1\Editor\Unity.exe" -batchmode -nographics -projectPath . -runTests -testPlatform EditMode -testResults TestResults-EditMode.xml -logFile Logs/tests-editmode.log
  ```

  Если путь к Unity другой или проект открыт — попроси меня запустить тесты в окне Test Runner
  и прислать результат.
