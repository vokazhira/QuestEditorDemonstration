# Журнал решений

Решения, принятые самостоятельно там, где спецификация оставляет выбор. Формат: дата, решение, причина.
Новые записи добавляются в конец; пересмотренное решение не удаляется, а помечается «заменено D-NNN».

---

### D-001 · 2026-11-02 · Имена пакета и namespace: `com.vokazhira.quest-editor` / `Vokazhira.QuestEditor`
**Решение:** пакет `com.vokazhira.quest-editor`; namespaces `Vokazhira.QuestEditor` (Runtime) и
`Vokazhira.QuestEditor.Editor` (Editor); сборки называются так же. Заглушки `YourName` заменены во всех документах.
**Причина:** имя namespace и сборки входит в сериализованные данные `[SerializeReference]`;
переименование после появления ассетов потребовало бы `[MovedFrom]` на каждом классе узла.
Имена подтверждены заказчиком до этапа 1.

### D-002 · 2026-11-02 · Один текущий узел на экземпляр; мгновенные узлы проходятся в цикле
**Решение:** `QuestGraphRunner` из текущего узла проходит Start и Condition подряд до первого
Objective или End. Лимит — 1000 шагов за один вызов, превышение = ошибка в лог и квест переходит в `Failed`.
**Причина:** спецификация запрещает параллельные ветки и циклы; лимит — дешёвая страховка на
случай, если невалидный граф всё же попадёт в исполнение.

### D-003 · 2026-11-02 · В сохранение попадает только «устойчивый» узел
**Решение:** `currentNodeId` всегда указывает на Objective или End (для `Claimable`).
**Причина:** Condition при загрузке не вычисляется повторно — результат не зависит от того,
изменились ли состояния других квестов между сохранением и загрузкой.

### D-004 · 2026-11-02 · Тестовая сборка `Tests.Runtime` — Editor-only и не ссылается на Editor-сборку пакета
**Решение:** `Vokazhira.QuestEditor.Tests.Runtime.asmdef`: `includePlatforms: ["Editor"]`, ссылки только на
Runtime-сборку пакета и TestRunner. Тесты в ней — EditMode.
**Причина:** спецификация требует EditMode-тестов runtime-логики и команду запуска с
`-testPlatform EditMode`; сборка без платформенных ограничений попала бы в PlayMode. Отсутствие ссылки на
Editor-сборку пакета гарантирует, что логика тестируется без редакторского кода. PlayMode-тестов в MVP нет.

### D-005 · 2026-11-02 · Стабильные id портов — строковые константы
**Решение:** `QuestPortIds`: `in`, `out`, `true`, `false`, `reward`, `rewards`.
**Причина:** связи хранят id портов; подпись порта (`displayName`) можно менять без потери данных.

### D-006 · 2026-11-02 · Единственный Start удалить нельзя
**Решение:** если удаляется последний Start, он исключается из удаления, а окно показывает уведомление.
Лишние Start (их может быть несколько, если граф уже невалиден) удаляются как обычно.
**Причина:** граф без Start всегда невалиден, а восстановить его можно только через Undo; запрет проще и понятнее предупреждения.

### D-007 · 2026-11-02 · Запуск квеста только из `Available`
**Решение:** `CanStart` = состояние `Available` + граф без ошибок. Повторный запуск `Completed`/`Failed` в MVP не поддерживается.
**Причина:** спецификация не описывает повторяемые квесты; иначе пришлось бы решать, что делать с
уже выданными `RewardId`.

### D-008 · 2026-11-02 · `package.json` без зависимости от `com.unity.test-framework`
**Решение:** в `dependencies` пакета не указываем Test Framework.
**Причина:** тесты нужны только при разработке пакета; в проекте UTF 1.3.9 уже есть (через
`com.unity.feature.development`). Тестовые asmdef защищены `defineConstraints: ["UNITY_INCLUDE_TESTS"]`,
поэтому у пользователя пакета без UTF ничего не сломается.

### D-009 · 2026-11-02 · Поиск обработчика награды: точный тип, затем базовые типы
**Решение:** `QuestRewardDispatcher` ищет `IRewardHandler<T>` по точному типу награды, затем вверх по иерархии
до `RewardNodeData`.
**Причина:** пользователь может зарегистрировать один обработчик на базовый класс своих наград.

### D-010 · 2026-11-02 · Copy/Paste узлов в GraphView отключено
**Решение:** обработчики сериализации и вставки GraphView не реализуются.
**Причина:** раздел 9 спецификации — не делать в MVP; иначе GraphView вставил бы элементы, у которых нет модели.

### D-011 · 2026-11-02 · Отсутствующий `currentNodeId` при загрузке: квест «заморожен»
**Решение:** экземпляр восстанавливается с сохранённым состоянием, но не исполняется (события
игнорируются), в лог пишется предупреждение с questId и nodeId. При следующем сохранении запись
сохраняется без изменений.
**Причина:** прогресс игрока не теряется и не искажается молча; после исправления графа (или
возврата узла) квест продолжит работу. Окончательно подтверждается на этапе 7.

### D-012 · 2026-11-02 · Индикатор `*` — флаг, а не сравнение с ассетом (заменено D-025)
**Решение:** любое изменение рабочей копии ставит флаг; Save/Discard сбрасывает. Если Undo вернул граф к
сохранённому виду, `*` останется.
**Причина:** побайтное сравнение с ассетом на каждое изменение — лишняя сложность; ложное «есть изменения»
безопаснее, чем ложное «изменений нет».

### D-013 · 2026-11-02 · Порядок обработки событий — порядок квестов в `QuestDatabase`
**Решение:** `Report` проходит активные экземпляры в порядке списка базы.
**Причина:** детерминированность (тесты, повторяемость при загрузке).

### D-014 · 2026-11-02 · Нет обработчика награды при старте квеста — предупреждение, не отказ
**Решение:** `Start` проверяет, что для каждой награды графа есть обработчик; если нет — предупреждение в лог,
но квест запускается.
**Причина:** спецификация (5.2) уже описывает поведение при невыданной награде: квест остаётся `Claimable`,
награду можно получить повторным `Claim` после регистрации обработчика. Отказ в запуске сделал бы порядок
регистрации сервисов хрупким.

### D-015 · 2026-11-02 · Комментарии в коде — только `<summary>` и `[Tooltip]`
**Решение:** не оставлять `//`-комментарии рядом с полями и перед методами; пояснения — через XML-документацию
`/// <summary>` и атрибут `[Tooltip]`. Правило добавлено в CLAUDE.md.
**Причина:** требование заказчика.

### D-016 · 2026-11-02 · Зависимости `package.json` — только встроенные модули
**Решение:** `dependencies`: `com.unity.modules.jsonserialize` и `com.unity.modules.uielements` (обе версии 1.0.0,
есть в `Packages/manifest.json` проекта). GraphView и IMGUI входят в редактор и не требуют пакетов.
`"unity": "2023.1"` без `unityRelease`.
**Причина:** спецификация разрешает только подтверждённые зависимости; пакет использует `JsonUtility`
(сохранения) и UI Toolkit (редактор). Сторонних пакетов нет.

### D-017 · 2026-11-02 · Пустые asmdef на этапе 1
**Решение:** на этапе 1 сборки не содержат `.cs`-файлов; заглушечные классы не создаются.
**Причина:** CLAUDE.md запрещает пустые классы ради структуры. Unity не компилирует asmdef без скриптов,
поэтому реальная компиляция сборок проверяется на этапе 2, когда появится код.

### D-018 · 2026-11-02 · `QuestNodeData.Validate` и `QuestValidationContext` переносятся на этап 5
**Решение:** на этапе 2 у узлов нет метода `Validate`; он появится вместе с валидатором, контекстом и `QuestDiagnostic`.
**Причина:** без диагностики контекст был бы пустой заглушкой (запрещено CLAUDE.md). Добавление виртуального
метода позже не ломает сериализованные данные.

### D-019 · 2026-11-02 · Один namespace на все runtime-файлы
**Решение:** все типы Runtime-сборки лежат в `Vokazhira.QuestEditor` независимо от подпапки (`Graph/`, `Nodes/` ...).
**Причина:** полное имя типа входит в данные `[SerializeReference]`; перенос файла между папками не должен
менять namespace и ломать ассеты. Пользователю достаточно одного `using`.

### D-020 · 2026-11-02 · `RequiredCount` — абстрактное свойство только для чтения
**Решение:** `ObjectiveNodeData.RequiredCount { get; }` абстрактное; у каждой встроенной цели своё поле
`requiredCount` и метод `SetRequiredCount(int)`.
**Причина:** так требует спецификация (2.3); пользовательская цель может вычислять требуемое количество
иначе или не хранить его. Сеттер у переопределения абстрактного get-only свойства в C# 9 добавить нельзя.

### D-021 · 2026-11-02 · `ObjectiveId` и `RewardId` по умолчанию — новый GUID
**Решение:** генерируются в конструкторе (как `Id` узла), но редактируются в инспекторе.
**Причина:** значение сразу непустое и уникальное; дизайнер может заменить его на читаемое. Пустые и
повторяющиеся значения ловит валидатор (этап 5).

### D-022 · 2026-11-02 · `QuestObjectiveMatching` — публичный помощник
**Решение:** проверка «тип события + targetId» для целей вынесена в публичный статический класс без состояния.
**Причина:** убирает дублирование у трёх встроенных целей и пригодится пользовательским целям. Это чистая функция,
а не менеджер.

### D-023 · 2026-11-02 · Тест сохранения ассета пишет во временную папку `Assets/QuestEditorTestsTemp`
**Решение:** тест `AssetDatabaseSave_*` создаёт ассет в этой папке и удаляет её в TearDown. Отдельный тест
делает настоящую перезагрузку через `InternalEditorUtility.SaveToSerializedFileAndForget` /
`LoadSerializedFileAndForget` в `Temp/`.
**Причина:** `AssetDatabase.LoadAssetAtPath` сразу после `CreateAsset` возвращает тот же объект из памяти,
поэтому сам по себе не доказывает round-trip; второй тест получает новый экземпляр из файла.

### D-024 · 2026-11-02 · Тексты для пользователя — на русском (заменено D-078)
**Решение:** `GetSummary()`, причины отказа `QuestPortRules`, пункты меню `[QuestNode]` — на русском;
сообщения исключений для программиста — на английском.
**Причина:** спецификация и README на русском; локализация в MVP не делается (раздел 9).

### D-025 · 2026-11-02 · Несохранённые изменения определяются сравнением JSON-снимка
**Решение:** `QuestWorkingCopy` хранит `EditorJsonUtility.ToJson` рабочей копии на момент открытия или сохранения
и сравнивает его с текущим состоянием при каждом изменении и Undo. Черновик (без ассета) всегда «не сохранён».
Заменяет D-012.
**Причина:** точнее флага: Undo до сохранённого состояния снимает `*`, лишние события привязки PropertyField не дают
ложной `*`. Графы заданий маленькие, сериализация на каждое изменение дешёвая.

### D-026 · 2026-11-02 · New — черновик в памяти, «Создать» в библиотеке — сразу ассет
**Решение:** New открывает черновик (Start + End(Completed), без связи), путь спрашивается при первом Save.
«Создать» в библиотеке спрашивает путь, создаёт ассет с тем же содержимым и открывает его. Существующий файл
«Создать» не перезаписывает.
**Причина:** спецификация называет обе команды; так у них разный смысл, и New не плодит файлы в проекте.

### D-027 · 2026-11-02 · Удаление задания — в корзину ОС
**Решение:** «Удалить» вызывает `AssetDatabase.MoveAssetToTrash` после подтверждения; если задание открыто,
окно закрывает его (в диалоге предупреждение о потере несохранённых изменений).
**Причина:** удаление можно отменить из корзины; это опасная операция (раздел 8 спецификации).

### D-028 · 2026-11-02 · Save As и «Копия» назначают уникальный questId при совпадении
**Решение:** если questId уже занят другим ассетом проекта, добавляется суффикс `_2`, `_3`…; окно показывает
уведомление. Обычный Save questId не меняет — повтор ловит валидатор (этап 5).
**Причина:** спецификация требует нового questId при дублировании; Save As фактически создаёт копию.

### D-029 · 2026-11-02 · Панель настроек задания сделана на этапе 3a, раскрывающейся панелью
**Решение:** кнопка «Настройки» на верхней панели показывает под ней поля questId, displayName, description,
rewardMode (PropertyField на SerializedObject рабочей копии). В Architecture.md она называлась `QuestSettingsPopup`,
файл называется `QuestSettingsPanel`.
**Причина:** без редактируемых полей на этапе 3a нельзя проверить индикатор `*`, Undo и диалог несохранённых изменений.
Встроенная панель проще и надёжнее `PopupWindow`. На этапе 4 панель дорабатывается при необходимости.

### D-030 · 2026-11-02 · Задание в библиотеке открывается двойным кликом или Enter
**Решение:** одиночный клик только выделяет (для «Копия» / «Удалить»), открытие — `ListView.itemsChosen`.
**Причина:** открытие по одиночному клику вызывало бы диалог несохранённых изменений при простом выделении.

### D-031 · 2026-11-02 · После `CopySerialized` имя и HideFlags ассета восстанавливаются явно
**Решение:** Save запоминает имя ассета, вызывает `EditorUtility.CopySerialized(workingCopy, asset)`, затем
возвращает имя и ставит `hideFlags = None`.
**Причина:** `CopySerialized` копирует все сериализованные поля объекта; без этого рабочая копия могла бы
передать ассету своё имя или флаг `DontSave`. Тест `Save_CopySerializedTransfersManagedReferenceNodes` проверяет и это.

### D-032 · 2026-11-02 · Открытый ассет удалён извне — копия становится черновиком
**Решение:** при событии библиотеки, если ассет по GUID больше не найден, рабочая копия отвязывается и помечается
несохранённой; окно показывает уведомление. Перемещение/переименование не мешает: ассет ищется по GUID.
**Причина:** работа пользователя не теряется молча.

### D-033 · 2026-11-02 · Классы редактора — `internal`, тесты через `InternalsVisibleTo`
**Решение:** окно, рабочая копия и утилиты — `internal`; `Editor/AssemblyInfo.cs` открывает их сборке
`Vokazhira.QuestEditor.Tests.Editor`.
**Причина:** редакторские классы не являются публичным API пакета.

### D-034 · 2026-11-02 · Ширина библиотеки фиксирована (260 px), без `TwoPaneSplitView`
**Решение:** раскладка окна — обычные flex-контейнеры.
**Причина:** нет уверенности в публичности и поведении `TwoPaneSplitView` в 2023.1; перетаскиваемый разделитель —
украшение, не требование MVP.

### D-035 · 2026-11-02 · На этапе 3b связи только отображаются
**Решение:** существующие связи из модели рисуются, но их нельзя выделить и удалить; `GetCompatiblePorts` возвращает
пустой список, поэтому новые связи не создаются. Связь удаляется только вместе с узлом. Создание и удаление связей —
этап 3c.
**Причина:** граф должен выглядеть правильно сразу после открытия, но синхронизация связей с моделью относится к 3c.

### D-036 · 2026-11-02 · Положение и масштаб холста хранятся в окне
**Решение:** `viewTransformChanged` сохраняет позицию и масштаб в `[SerializeField]` окна; после domain reload вид
восстанавливается. При открытии другого задания вызывается `FrameAll`.
**Причина:** «сохранение раскладки» из раздела 8 спецификации; в ассет задания вид не пишется — это не данные квеста.

### D-037 · 2026-11-02 · Узлы с отсутствующим типом на холсте не показываются
**Решение:** `null`-элементы списка `nodes` (класс удалён) пропускаются; их связи тоже не рисуются. Данные в ассете
остаются как есть.
**Причина:** узнать порты такого узла нельзя. Сообщение об ошибке даст валидатор (этап 5, правило 10).

### D-038 · 2026-11-02 · Copy / Cut / Duplicate в GraphView отключены через capabilities
**Решение:** у узлов и связей снят флаг `Capabilities.Copiable`, поэтому пункты меню недоступны. Реализует D-010.
**Причина:** копирование узлов вне MVP (раздел 9).

### D-039 · 2026-11-02 · `ContentZoomer` подключается через `SetupZoom`
**Решение:** зум включается вызовом `SetupZoom(ContentZoomer.DefaultMinScale, ContentZoomer.DefaultMaxScale)`, который
сам добавляет `ContentZoomer`; отдельный `AddManipulator(new ContentZoomer())` не нужен.
**Причина:** так GraphView синхронизирует пределы зума с манипулятором.

### D-040 · 2026-11-02 · Связь к занятому single-порту заменяет старую
**Решение:** `GetCompatiblePorts` не учитывает занятость single-портов. При соединении стандартный обработчик GraphView
сначала удаляет старую связь single-порта, затем создаётся новая; обе операции попадают в Undo.
**Причина:** привычное поведение GraphView: перетянуть выход на другой узел, не удаляя сначала старую связь.
Модель всё равно проверяет capacity в `QuestPortRules.CanConnect`.

### D-041 · 2026-11-02 · Flow-циклы отклоняются уже при создании связи
**Решение:** добавлен `QuestPortRules.WouldCreateFlowCycle` (Runtime). Редактор отказывает в связи, замыкающей цикл,
и показывает уведомление «Связь отклонена: …». В `GetCompatiblePorts` циклы не отфильтрованы — порт подсвечивается,
а при отпускании пользователь видит причину отказа. Валидатор (этап 5) переиспользует ту же проверку для графов,
изменённых вне редактора.
**Причина:** раздел 2.1: циклы запрещены, редактор показывает ошибку. Отказ сразу проще, чем разрешить и подсветить
ошибку позже. Ограничение: если новая связь от занятого single-выхода отклонена из-за цикла, старая связь уже удалена
(D-040); Ctrl+Z возвращает её.

### D-042 · 2026-11-02 · Несовместимые порты не подсвечиваются при перетаскивании связи
**Решение:** направление, вид порта, связь с самим собой и дубликаты фильтруются в `GetCompatiblePorts` — к таким
портам связь просто не прилипает, отдельного сообщения нет. Сообщение показывается, когда отказывает модель.
**Причина:** стандартное поведение GraphView; в момент «отпускания мимо порта» GraphView не сообщает, к какому порту
пытались подключиться.

### D-043 · 2026-11-02 · Инспектор показывает поля узла по отдельности
**Решение:** вместо одного `PropertyField` на весь `nodes.Array.data[i]` (он рисуется свёрнутым foldout'ом) инспектор
обходит видимые дочерние свойства managed reference и создаёт `PropertyField` для каждого. Инспектор один для всех типов,
в том числе пользовательских; `[HideInInspector]`-поля `id` и `position` не показываются.
**Причина:** без лишнего foldout'а интерфейс проще; `[Tooltip]`, `[TextArea]`, `[Min]` работают как обычно.

### D-044 · 2026-11-02 · Пропавшие порты — связи удаляются автоматически, с уведомлением и Undo
**Решение:** после изменения поля узла окно сравнивает порты на холсте с портами модели. Если набор изменился
(End: Completed → Failed убирает порт «Награды»), связи к исчезнувшим портам удаляются через Undo, холст пересобирается,
окно показывает «Удалено связей к исчезнувшим портам: N». Ctrl+Z возвращает и поле, и связи.
**Причина:** иначе в модели остались бы «висячие» связи, которые нельзя увидеть и удалить на холсте. Работает и для
пользовательских узлов с динамическими портами.

### D-045 · 2026-11-02 · Настройки задания остаются на верхней панели
**Решение:** требование этапа 4 «настройки квеста» закрыто панелью из этапа 3a (D-029); в инспекторе узла они не дублируются.
**Причина:** одно место для настроек задания, один источник изменений.

### D-046 · 2026-11-02 · Инспектор пересоздаётся только при смене узла или его индекса
**Решение:** перемещения и прочие изменения графа не пересоздают поля инспектора, если выделен тот же узел с тем же
индексом в `nodes`. Undo всегда пересоздаёт инспектор.
**Причина:** иначе поле теряло бы фокус во время ввода; индекс важен, потому что путь `nodes.Array.data[i]` от него зависит.

### D-047 · 2026-11-02 · Отсутствующий тип узла: рантайм видит `null`, редактор — имя класса
**Решение:** `QuestGraphValidator` (Runtime) сообщает QE018 для каждого `null`-элемента `nodes` — так Unity
представляет managed reference с удалённым классом. Редактор дополнительно вызывает
`UnityEditor.SerializationUtility.HasManagedReferencesWithMissingTypes` / `GetManagedReferencesWithMissingTypes` и добавляет
диагностику с именем класса и сборки. Save ассета с отсутствующими типами требует подтверждения.
**Причина:** `SerializationUtility` из спецификации — редакторский API (namespace `UnityEditor`), Runtime-сборке он
недоступен. Подтверждение при сохранении — потому что рабочая копия не содержит данных узлов неизвестного типа и их
перезапись ассета потеряла бы.

### D-048 · 2026-11-02 · Коды диагностик
**Решение:** `QuestDiagnosticCodes`: QE001…QE020 — ошибки, QW001…QW004 — предупреждения. Исключение в `Validate`
пользовательского узла не роняет валидатор, а превращается в QE020.
**Причина:** стабильные коды удобно искать в логах и упоминать в документации.

### D-049 · 2026-11-02 · Все Flow-порты узла обязательны
**Решение:** правило 8 требует подключения каждого Flow-входа и Flow-выхода, в том числе обеих веток Condition.
**Причина:** неподключённый выход означает, что задание «застрянет» в узле при исполнении. Необязательных Flow-портов
в MVP нет.

### D-050 · 2026-11-02 · Правило 9 и правило 11 без двойных сообщений
**Решение:** «End не достижим из Start» — ошибка, если не достижим ни один End; отдельные недостижимые узлы — предупреждение
QW001 (награды из этой проверки исключены, их покрывает QW002). Связь награды с портом, которого нет (End переключён
на Failed), — ошибка правила 3 (QE005), а не правила 11; QE019 — только когда порт наград есть, но узел не End(Completed).
**Причина:** одна проблема — одно сообщение; несколько End с недостижимым «запасным» финалом — допустимая ситуация.

### D-051 · 2026-11-02 · Валидация в окне: при открытии, Validate и Save; метка «устарело» по снимку
**Решение:** помимо Validate и Save, проверка запускается при открытии задания. Панель показывает «результаты могли
устареть», если JSON-снимок рабочей копии отличается от снимка на момент проверки (Undo к проверенному состоянию метку снимает).
**Причина:** пользователь сразу видит состояние задания; лишних запусков на каждое изменение нет.

### D-052 · 2026-11-02 · Библиотека проверяет сохранённые ассеты при каждом обновлении
**Решение:** при Refresh библиотека валидирует каждый ассет (не рабочую копию) и показывает значок ошибки с первой
ошибкой во всплывающей подсказке.
**Причина:** спецификация: «в библиотеке невалидный граф помечен». Обновление происходит только по событию, не каждый кадр.

### D-053 · 2026-11-02 · Дополнительные проверки значений
**Решение:** к правилу 7 добавлены ошибки «пустой ObjectiveId», «пустой RewardId», «пустой questId у условия
QuestCompletedCondition».
**Причина:** по ObjectiveId хранится прогресс, по RewardId — выданные награды; условие без questId всегда ложно.

### D-054 · 2026-11-02 · Повреждённые графы в тестах строятся через reflection
**Решение:** `Tests/Runtime/QuestTestGraphs` добавляет «сырые» связи и узлы и меняет Id узла через reflection.
**Причина:** публичный API модели не позволяет создать невалидные данные, а добавлять в Runtime методы только для тестов
не хочется.

### D-055 · 2026-11-02 · Конструктор `QuestManager` на этапе 6 — только с базой заданий
**Решение:** `new QuestManager(QuestDatabase database)`. Параметр `IQuestSaveService` добавляется на этапе 7 вместе
с самим интерфейсом и DTO сохранений.
**Причина:** интерфейс сохранений ссылается на DTO этапа 7; заглушки сейчас были бы пустыми классами.

### D-056 · 2026-11-02 · Игра получает `QuestInstance` напрямую, без отдельного интерфейса «вида»
**Решение:** `GetInstances()` / `GetInstance()` возвращают `QuestInstance`; все изменяющие методы и сеттеры — `internal`.
`IQuestInstanceView` из Architecture.md не создаётся.
**Причина:** снаружи экземпляр и так только читается; лишний интерфейс — абстракция «на будущее».

### D-057 · 2026-11-02 · События передают `QuestInstance`; добавлено событие `QuestClaimable`
**Решение:** `QuestStarted/Completed/Failed/Claimable(QuestInstance)`, `QuestProgressChanged(QuestInstance, ObjectiveNodeData, int)`,
`QuestRewardGranted(QuestInstance, RewardNodeData)`, `QuestRewardFailed(QuestInstance, RewardNodeData, string reason)`.
`QuestClaimable` вызывается, когда задание дошло до End(Completed), но награды ещё не выданы (ManualClaim или ошибка выдачи).
**Причина:** UI нужны название, цель и требуемое количество без повторного поиска; без `QuestClaimable` игра не узнает,
что пора показать кнопку «Забрать награду».

### D-058 · 2026-11-02 · Неизвестный questId
**Решение:** `GetState` возвращает `Available`, `GetInstance` — null, `Start`/`Claim`/`Abandon` — false
(Start пишет предупреждение). Добавлен `GetValidationErrors(questId)`.
**Причина:** условия других заданий могут ссылаться на ещё не добавленные в базу задания — исключение там неуместно.

### D-059 · 2026-11-02 · Невалидное задание: регистрируется, но не запускается
**Решение:** при создании менеджер валидирует каждое задание базы (с проверкой уникальности questId внутри базы);
при ошибках пишет `Debug.LogError` со списком ошибок, задание остаётся `Available`, `CanStart` = false.
Задание с пустым или уже занятым questId не регистрируется вовсе.
**Причина:** раздел 2.4: исполнять можно только граф без ошибок; причина видна в логе и через `GetValidationErrors`.

### D-060 · 2026-11-02 · Сбой исполнения графа во время игры → Failed
**Решение:** если исполнитель не может продолжить (нет связи, неизвестный узел, исключение в условии, лимит шагов),
задание переходит в `Failed`, в лог пишется ошибка, вызывается `QuestFailed`.
**Причина:** для валидного графа это невозможно; если всё же случилось, задание не должно «зависнуть» в Active. Дополняет D-002.

### D-061 · 2026-11-02 · `Report` устойчив к ошибкам и повторному входу
**Решение:** события обходят снимок списка экземпляров; исключение при обработке одного задания логируется и не мешает
остальным.
**Причина:** обработчики событий игры могут сами запускать задания или сообщать события.

### D-062 · 2026-11-02 · Порядок выдачи наград и событий
**Решение:** при входе в End(Completed) задание сначала становится `Claimable`, затем награды выдаются в порядке связей,
после каждой — `QuestRewardGranted`; если выданы все — `Completed` и `QuestCompleted`.
**Причина:** раздел 2.1: награда не выдаётся до смены состояния задания; повторный `Claim` выдаёт только невыданные RewardId.

### D-063 · 2026-11-02 · `QuestDatabase` заполняется в редакторе через SerializedObject
**Решение:** список заданий публично только читается; кнопка «Собрать все задания проекта» в инспекторе меняет его через
`SerializedObject` (с Undo) и показывает число заданий с ошибками. `SetQuests` — `internal`, для тестов.
**Причина:** база — определение игры, а не прогресс; менять её из игрового кода незачем.

### D-064 · 2026-11-02 · Тестовые вспомогательные классы — по одному на файл
**Решение:** `QuestValidatorTestNodes.cs` (этап 5) разделён на `RewardSinkTestNode.cs` и `ThrowingValidationTestNode.cs`;
старый файл и его `.meta` удалены.
**Причина:** правило CLAUDE.md «один класс — один файл».

### D-065 · 2026-11-02 · `QuestManager` принимает необязательный `UnityEngine.ILogger` (реализуется на этапе 7)
**Решение:** на этапе 7 конструктор станет `QuestManager(QuestDatabase database, IQuestSaveService saveService, ILogger logger = null)`;
без логгера используется `Debug.unityLogger`. Все сообщения менеджера идут через него. Тесты передают логгер, который
запоминает сообщения и ничего не выводит, и проверяют их вместо `LogAssert.Expect`.
**Причина:** решение заказчика: ожидаемые ошибки тестов не должны оставаться в Console; игра получает контроль над
логами заданий (фильтр, перенаправление). Конструктор на этапе 7 всё равно меняется.

### D-066 · 2026-11-02 · DTO сохранений — открытые поля, состояние строкой
**Решение:** `QuestSaveData`, `QuestInstanceSaveData`, `ObjectiveProgressEntry` — `[Serializable]` классы с открытыми полями
(как требует JsonUtility). `state` хранится именем значения `QuestState` («Active»), а не числом.
**Причина:** перестановка или добавление значений в перечислении не испортит старые сохранения.

### D-067 · 2026-11-02 · Правила `Restore` (уточняет D-011)
**Решение:**
- все задания сначала сбрасываются в `Available`, затем применяются записи; задания без записи остаются `Available`;
- запись задания, которого нет в базе, попадает в `orphanedQuests` и сохраняется обратно без изменений; если задание
  вернулось в базу, запись из `orphanedQuests` восстанавливается как обычная;
- задание **замораживается** (`QuestInstance.IsFrozen`), если: неизвестное имя состояния; `Active`, но сохранённого узла
  нет или это не цель; `Claimable`, но узел не End(Completed); `Active`/`Claimable`, а граф содержит ошибки. Замороженное
  задание не получает события, его нельзя запустить, прервать или забрать награду, а запись сохраняется обратно как есть;
  в лог — предупреждение;
- при повторе записи одного задания используется первая (сначала `quests`, потом `orphanedQuests`);
- если после загрузки текущая цель уже выполнена (требуемое количество уменьшили), задание сразу продвигается дальше.
**Причина:** прогресс игрока не теряется и не искажается молча; после исправления графа задание продолжит работу.

### D-068 · 2026-11-02 · Версия формата сохранения
**Решение:** `QuestSaveData.CurrentVersion = 1`. Сохранение более новой версии не загружается (`Restore` → false,
состояние не меняется, ошибка в лог). Более старая версия загружается как есть с предупреждением — миграций пока нет.
**Причина:** нельзя молча читать формат, о котором код ничего не знает; старый формат пока отличается только номером.

### D-069 · 2026-11-02 · `FileQuestSaveService`
**Решение:** путь — абсолютный или относительно `Application.persistentDataPath` (по умолчанию `quests.json`). Запись:
`<файл>.tmp` → `File.Replace`; если платформа не поддерживает `File.Replace`, — копирование с перезаписью и удаление
временного файла. Нет файла — пустое сохранение без ошибки. Пустой или неразбираемый файл — ошибка, копия в
`<файл>.corrupt` (перезаписывается при следующем повреждении), исходный файл не трогается до следующего `Save`.
**Причина:** раздел 6 спецификации; `File.Replace` доступен не на всех платформах Unity.

### D-070 · 2026-11-02 · `IQuestSaveService` в конструкторе может быть null
**Решение:** без сервиса работают `Capture` / `Restore`, а `Save` / `Load` возвращают false и пишут ошибку в лог.
Ошибки сервиса (исключения, `TryLoad` = false) тоже не выбрасываются наружу: false + лог, состояние не меняется.
**Причина:** игра может хранить прогресс в своём формате сохранений; падение из-за диска не должно ломать игру.

### D-071 · 2026-11-02 · Логгер реализован (D-065)
**Решение:** все сообщения `QuestManager` идут через `ILogger` с тегом `QuestManager`. Тесты передают
`new Logger(new TestLogHandler())` и проверяют сообщения в нём; `LogAssert.Expect` больше не используется.
**Причина:** решение заказчика (D-065).

### D-072 · 2026-11-02 · Сцену и ассеты демо создаёт редакторская команда
**Решение:** `Tools → Quest Editor → Demo → Build Demo Assets` (`QuestDemoAssetBuilder`) создаёт рядом со своей папкой
`Quests/IntroQuest.asset`, `Quests/ForestCleanup.asset`, `QuestDemoDatabase.asset` и `QuestDemo.unity` с объектом `QuestDemo`
(bootstrap + UI, ссылки назначены через SerializedObject). Результат и сгенерированные Unity `.meta` коммитит заказчик.
**Причина:** сцена и ассеты ссылаются на скрипты и друг на друга по GUID из `.meta`, которые создаёт только Unity;
вручную такой YAML не написать корректно. Команда остаётся в примере, чтобы демо можно было пересоздать.

### D-073 · 2026-11-02 · Интерфейс демо — IMGUI
**Решение:** `QuestDemoUI` рисует интерфейс в `OnGUI`.
**Причина:** не нужны Canvas, шрифты, PanelSettings и другие ассеты; для демонстрации API этого достаточно.

### D-074 · 2026-11-02 · Содержимое демо
**Решение:** два задания. «Письмо старосты» (`intro`, AutoGrant): найти письмо → 10 золота. «Зачистка леса»
(`forest_cleanup`, ManualClaim): убить 10 гоблинов → «intro выполнено?» → да: финал с 100 золота и 25 опыта (кнопка

### D-075 · 2026-11-02 · Этап 8 в два шага
**Решение:** сначала демо живёт в `Assets/QuestEditorDemo/` (код, команда сборки); после того как заказчик создаст ассеты
и закоммитит их вместе с `.meta`, папка переносится в `Packages/com.vokazhira.quest-editor/Samples~/BasicQuestExample/`,
а в `package.json` добавляется раздел `samples`.
**Причина:** `Samples~` Unity не импортирует, поэтому `.meta` для примера нужно получить заранее в `Assets/`.

### D-076 · 2026-11-02 · Исправление команды сборки демо; повторная сборка сохраняет GUID
**Решение:** после `EditorSceneManager.NewScene(…, Single)` база заданий загружается заново по пути; ассеты, которые уже
существуют, обновляются через `EditorUtility.CopySerialized`, а не удаляются и создаются заново. Сцена сохраняется по тому же
пути, поэтому её `.meta` тоже не меняется.
**Причина:** при первой сборке ссылка на базу в сцене оказалась пустой (`database: {fileID: 0}`) — `NewScene` в режиме
Single выгрузил неиспользуемые ассеты, и полученная ранее ссылка стала недействительной. Сохранение GUID делает повторную
сборку безопасной для закоммиченных `.meta`.

### D-077 · 2026-11-02 · Демо перенесено в `Samples~/BasicQuestExample`
**Решение:** содержимое `Assets/QuestEditorDemo/` вместе с `.meta` перенесено в
`Packages/com.vokazhira.quest-editor/Samples~/BasicQuestExample/`; `.meta` самой папки `Assets/QuestEditorDemo` удалён
(при импорте примера Unity создаёт папку заново). В `package.json` добавлен раздел `samples`.
**Причина:** этап 8 спецификации и D-075. `.meta` внутри примера сохраняют GUID, поэтому после импорта ссылки сцены на базу,
базы на задания и всех ассетов на скрипты пакета остаются целыми.

### D-078 · 2026-11-02 · Пользовательские тексты — на английском (заменяет D-024)
**Решение:** интерфейс редактора, пути меню `[QuestNode]` (`Flow/Start`, `Objectives/Kill Enemies`…), заголовки
(`GetSummary`) и подписи портов узлов, `[Tooltip]`, причины отказа `QuestPortRules`, сообщения валидатора, `QuestManager`
и `FileQuestSaveService`, демо (код и ассеты заданий), описания в `package.json` — на английском. README: основной
английский, второй — русский. XML-документация в коде и `Docs/` остаются на русском. Правило записано в CLAUDE.md.
**Причина:** решение заказчика: пакет рассчитан на переиспользование. Идентификаторы портов (`in`, `out`, `true`…) и данные
моделей не менялись, поэтому существующие ассеты совместимы.
