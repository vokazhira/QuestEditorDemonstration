# Журнал решений

Решения, принятые самостоятельно там, где спецификация оставляет выбор. Формат: дата, решение, причина.
Новые записи добавляются в конец; пересмотренное решение не удаляется, а помечается «заменено D-NNN».

---

### D-001 · 2026-11-02 · Имена `com.yourname.quest-editor` / `YourName.*` — ждут подтверждения
**Решение:** до ответа заказчика в документах используются имена из CLAUDE.md как есть.
**Причина:** имя namespace и сборки входит в сериализованные данные `[SerializeReference]`;
переименование после появления ассетов потребует `[MovedFrom]` на каждом классе узла.
Поэтому имя нужно зафиксировать до этапа 1 (вопрос задан в отчёте этапа 0).

### D-002 · 2026-11-02 · Один текущий узел на экземпляр; мгновенные узлы проходятся в цикле
**Решение:** `QuestGraphRunner` из текущего узла проходит Start и Condition подряд до первого
Objective или End. Лимит — 1000 шагов за один вызов, превышение = ошибка в лог и квест переходит в `Failed`.
**Причина:** спецификация запрещает параллельные ветки и циклы; лимит — дешёвая страховка на
случай, если невалидный граф всё же попадёт в исполнение.

### D-003 · 2026-11-02 · В сохранение попадает только «устойчивый» узел
**Решение:** `currentNodeId` всегда указывает на Objective или End (для `Claimable`).
**Причина:** Condition при загрузке не вычисляется повторно — результат не зависит от того,
изменились ли состояния других квестов между сохранением и загрузкой.

### D-004 · 2026-11-02 · Тестовая сборка `Tests.Runtime` — Editor-only и не ссылается на Editor-сборку пакета
**Решение:** `YourName.QuestEditor.Tests.Runtime.asmdef`: `includePlatforms: ["Editor"]`, ссылки только на
Runtime-сборку пакета и TestRunner. Тесты в ней — EditMode.
**Причина:** спецификация требует EditMode-тестов runtime-логики и команду запуска с
`-testPlatform EditMode`; сборка без платформенных ограничений попала бы в PlayMode. Отсутствие ссылки на
Editor-сборку пакета гарантирует, что логика тестируется без редакторского кода. PlayMode-тестов в MVP нет.

### D-005 · 2026-11-02 · Стабильные id портов — строковые константы
**Решение:** `QuestPortIds`: `in`, `out`, `true`, `false`, `reward`, `rewards`.
**Причина:** связи хранят id портов; подпись порта (`displayName`) можно менять без потери данных.

### D-006 · 2026-11-02 · Единственный Start удалить нельзя
**Решение:** если удаляется последний Start, он исключается из удаления, а окно показывает уведомление.
Лишние Start (их может быть несколько, если граф уже невалиден) удаляются как обычно.
**Причина:** граф без Start всегда невалиден, а восстановить его можно только через Undo; запрет проще и понятнее предупреждения.

### D-007 · 2026-11-02 · Запуск квеста только из `Available`
**Решение:** `CanStart` = состояние `Available` + граф без ошибок. Повторный запуск `Completed`/`Failed` в MVP не поддерживается.
**Причина:** спецификация не описывает повторяемые квесты; иначе пришлось бы решать, что делать с
уже выданными `RewardId`.

### D-008 · 2026-11-02 · `package.json` без зависимости от `com.unity.test-framework`
**Решение:** в `dependencies` пакета не указываем Test Framework.
**Причина:** тесты нужны только при разработке пакета; в проекте UTF 1.3.9 уже есть (через
`com.unity.feature.development`). Тестовые asmdef защищены `defineConstraints: ["UNITY_INCLUDE_TESTS"]`,
поэтому у пользователя пакета без UTF ничего не сломается.

### D-009 · 2026-11-02 · Поиск обработчика награды: точный тип, затем базовые типы
**Решение:** `QuestRewardDispatcher` ищет `IRewardHandler<T>` по точному типу награды, затем вверх по иерархии
до `RewardNodeData`.
**Причина:** пользователь может зарегистрировать один обработчик на базовый класс своих наград.

### D-010 · 2026-11-02 · Copy/Paste узлов в GraphView отключено
**Решение:** обработчики сериализации и вставки GraphView не реализуются.
**Причина:** раздел 9 спецификации — не делать в MVP; иначе GraphView вставил бы элементы, у которых нет модели.

### D-011 · 2026-11-02 · Отсутствующий `currentNodeId` при загрузке: квест «заморожен»
**Решение:** экземпляр восстанавливается с сохранённым состоянием, но не исполняется (события
игнорируются), в лог пишется предупреждение с questId и nodeId. При следующем сохранении запись
сохраняется без изменений.
**Причина:** прогресс игрока не теряется и не искажается молча; после исправления графа (или
возврата узла) квест продолжит работу. Окончательно подтверждается на этапе 7.

### D-012 · 2026-11-02 · Индикатор `*` — флаг, а не сравнение с ассетом
**Решение:** любое изменение рабочей копии ставит флаг; Save/Discard сбрасывает. Если Undo вернул граф к
сохранённому виду, `*` останется.
**Причина:** побайтное сравнение с ассетом на каждое изменение — лишняя сложность; ложное «есть изменения»
безопаснее, чем ложное «изменений нет».

### D-013 · 2026-11-02 · Порядок обработки событий — порядок квестов в `QuestDatabase`
**Решение:** `Report` проходит активные экземпляры в порядке списка базы.
**Причина:** детерминированность (тесты, повторяемость при загрузке).

### D-014 · 2026-11-02 · Нет обработчика награды при старте квеста — предупреждение, не отказ
**Решение:** `Start` проверяет, что для каждой награды графа есть обработчик; если нет — предупреждение в лог,
но квест запускается.
**Причина:** спецификация (5.2) уже описывает поведение при невыданной награде: квест остаётся `Claimable`,
награду можно получить повторным `Claim` после регистрации обработчика. Отказ в запуске сделал бы порядок
регистрации сервисов хрупким.
